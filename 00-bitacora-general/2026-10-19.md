# Bitácora general — Auditoría de coherencia y consolidación (2026-10-19)

## Objetivo

Revisar la coherencia del portfolio y del ecosistema de repositorios, corregir afirmaciones no respaldadas y añadir las capas de validación ofensiva, forense y cumplimiento.

## Contexto y alcance

- Repositorios públicos: portfolio, API, laboratorio de IA, perfil y web.
- Repositorios privados: curso y notas; no se publican.
- Revisión de READMEs, prácticas, CI, Bicep, web y metadatos.

## Hallazgos principales

1. El módulo 07 afirmaba SAST, IaC y pipeline bloqueante sin que el CI los ejecutara.
2. La API declaraba CORS restrictivo e IDs redactados, pero usaba `AllowAnyOrigin` y GUIDs reales.
3. Faltaba `LICENSE` en la API aunque el README lo enlazaba.
4. El escaneo de secretos fallaba por el commit raíz y Trivy no bloqueaba.
5. El módulo 05 no tenía las prácticas 05–07 que la web mostraba.
6. Las prácticas 01–04 de identidad tenían títulos duplicados y secciones desordenadas.
7. El laboratorio de IA exponía una IP interna y el nombre de un prompt privado.
8. La web describía módulos 03, 05 y 08 con contenido no respaldado.
9. El curso contenía credenciales de un VDI en texto plano.
10. Faltaba una capa de validación ofensiva, forense y cumplimiento.

## Trabajo realizado

- Endurecimiento de la API: CORS por allowlist, rate limiting, límites de cuerpo, DTOs, aislamiento de pedidos por usuario, ProblemDetails, health check y cabeceras.
- Pruebas de integración: 10 pruebas de autenticación, validación, mass assignment y BOLA.
- IaC: VNet, NSG, Key Vault, App Service, Private Endpoints y diagnóstico.
- CI: Gitleaks, CodeQL, Trivy SCA, contenedor no-root, Trivy config y Dependency Review.
- Módulo 07: matriz de estado real y limitaciones.
- Módulo 05: prácticas 05–07 de APIs, contenedores y storage, marcadas como diseño.
- Módulo 02: reescritura de las prácticas 01–04.
- Módulos 11 y 12: validación ofensiva y forense cloud.
- Matriz de cumplimiento con brechas declaradas.
- Corrección de la web y del perfil (en sus repositorios).

## Resultados

- La narrativa distingue implementado, validado, parcial, diseño y pendiente.
- La API tiene evidencia ejecutable y CI con gates.
- El portfolio incorpora validación ofensiva y forense sin presentarlas como producción.
- La matriz de cumplimiento evita afirmar certificaciones.

## Pendientes o riesgos

- Confirmar la primera ejecución verde del pipeline ampliado en GitHub Actions.
- Desplegar Bicep y validar Private Endpoints y diagnóstico.
- Ejecutar pruebas con tokens reales de Entra ID y dos usuarios delegados.
- Añadir autorización granular por scopes/roles.
- Ejecutar el tabletop de respuesta.
- Revisar la allowlist de Gitleaks y la justificación de Trivy.

## Aprendizaje

La coherencia no consiste en que todos los repositorios digan lo mismo, sino en que cada afirmación tenga el mismo nivel de evidencia. Un portfolio creíble separa arquitectura, implementación, validación y diseño.

## Siguiente paso

Convertir los estados “parcial” y “diseño” en evidencias ejecutadas, empezando por el pipeline y el despliegue de laboratorio.
