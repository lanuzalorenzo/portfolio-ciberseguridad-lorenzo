# 🛡️ 07 — DevSecOps (Política mínima de seguridad en repositorios)

Este módulo recoge la política DevSecOps mínima aplicada a los repositorios del portfolio.  
El objetivo es garantizar integridad, trazabilidad y control en el ciclo de vida del código mediante reglas de protección, revisión obligatoria y buenas prácticas de seguridad.

---

## 🧭 Objetivos del módulo

- Establecer una política DevSecOps mínima y obligatoria.
- Proteger la rama `main` frente a cambios no autorizados.
- Forzar el uso de Pull Requests como mecanismo de control.
- Garantizar trazabilidad en cada modificación del código.
- Documentar reglas, evidencias y decisiones técnicas.
- Unificar el comportamiento seguro de todos los repositorios del portfolio.

---

## 🧩 Contenido del módulo

Este módulo incluye:

### **1. Protección de la rama main**
- Bloqueo de push directo.
- Bloqueo de force‑push.
- Revisión obligatoria.
- Validaciones mínimas.

### **2. Política DevSecOps mínima**
- Reglas comunes para todos los repositorios.
- Flujo de trabajo seguro basado en PR.
- Buenas prácticas de control de versiones.
- Criterios de aprobación y trazabilidad.

### **3. Documentación técnica**
- Explicación de las reglas aplicadas.
- Justificación de decisiones de seguridad.
- Evidencias de configuración.

### **4. Bitácoras**
- Registros técnicos del proceso de configuración.
- Cambios aplicados y pruebas realizadas.

---

## ⚙️ Alcance del módulo

Este módulo se centra exclusivamente en:

- Seguridad del flujo Git.
- Protección de ramas.
- Reglas de revisión.
- Trazabilidad del código.

**No incluye:**
- CI/CD  
- Pipelines  
- SAST / SCA / DAST  
- Automatización avanzada  
- Integraciones externas  

Es una política mínima, estable y atemporal.
